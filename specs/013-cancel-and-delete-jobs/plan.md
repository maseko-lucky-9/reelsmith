# Implementation Plan: Cancel running jobs and delete finished ones

**Spec**: [spec.md](spec.md)

- **Task registry.** `app/workers/orchestrator.py` keeps `_job_tasks: dict[str, set[Task]]`, filled where `run_orchestrator` creates a task and emptied by a done callback, beside the reprompt registry (`_reprompts_in_flight`). `cancel_job(job_id)` adds the id to `_user_cancelled` and cancels the job's tasks; the id leaves the set when the job's last task is done. `job_active(job_id)` is true while the job has a task, a reprompt claim or a download thread.
- **User cancel versus shutdown.** Every cancel branch asks `job_id in _user_cancelled`. A run writes `cancelled` and emits `JobCancelled` through `_finish_then_honour_cancel` (as `_record_failure` does for a failure); a re-render calls `_restore_chapter_status`; a reprompt emits `RepromptFailed(reason="cancelled")` after the existing undo. A task cancelled while it waited for a slot (`_run_when_slot_free` now acquires the semaphore by hand, so it can tell) goes through `_cancel_before_start`, which also releases a reprompt claim the reprompt never got to release. Without the id in the set (a shutdown) every branch does what it did before.
- **Queued jobs.** A `pending`/`running` job with no task is marked `cancelled` by the route, which then asks the orchestrator to cancel any task the run got meanwhile; `_run_job` reads the stored status first, inside its `try`, so a cancel landing on that read is recorded, and does not start a cancelled job. `_record_cancel` only changes a `pending`/`running` job.
- **Worker threads.** `_job_thread` replaces `asyncio.to_thread` in the orchestrator: each thread counts itself in `_threads_running` from its first to its last line (a call cancelled before its thread started never runs and never counts), and `job_active` is true while any thread of the job runs. `_download_in_thread` counts the same way and sets the new `_yt_dlp_base.download_stop` context variable to a `threading.Event`, which the run sets as soon as its wait ends (cancel, timeout or success); `yt_dlp_download` adds a progress hook that raises `DownloadCancelled` once the check is true.
- **Status.** `cancelled` joins `JobStatus` (`app/domain/models.py`), `retention.TERMINAL_JOB_STATUSES` and the SSE `_TERMINAL_TYPES`; `JobCancelled` joins `EventType`. `jobs.status` is `String(32)`: no migration (`tests/unit/test_alembic_parity.py` stays green). `INTERRUPTIBLE_STATUSES` is unchanged: a cancelled job is final.
- **Delete.** `JobStoreProtocol.delete(job_id) -> bool` on both stores. `SqlJobStore` deletes the child rows itself, deepest first (scheduled posts, publish jobs, clip edits, analytics snapshots, share links, clips, chapters, the job) in one transaction: SQLite enforces `ON DELETE CASCADE` only with `PRAGMA foreign_keys=ON`, which the engine does not set. `list_clips` gains `include_retired` so the file delete sees every clip.
- **Files.** `retention.delete_job_files(job, store)` reads the other jobs' paths with `JobStoreProtocol.path_references` (path columns only; the SQL store takes the folders out of `jobs.state` by JSON key) and builds a keep set: folded spellings (`_spellings`: NFC/NFD, case-folded) and file identities of every other source, upload file, clip file and words sidecar, and the identities of the protected folders (`protected_roots()`). In a worker thread it accepts the job folder (`_job_folder`: canonical, no symlink in its path, strictly below a managed root, holding none, not protected), walks it when `_may_walk` allows (no protected folder inside, no overlap with another job's folder, by spelling or identity; the walk stops if it meets a protected folder by identity), and keeps named files to that folder, plus the adapter-recorded upload source (`_upload_source`). Each removal goes through `delete_below_root` with an `accept` that refuses a kept identity, read with `lstat` at deletion. `upload.uploaded_file` is the shared check for an uploaded file; `POST /jobs` uses it too.
- **Routes.** `POST /jobs/{id}/cancel` and `DELETE /jobs/{id}` in `app/routers/jobs.py` (also under `/api`, ADR-005). The delete takes `orchestrator.claim_delete` before its checks (the re-render and reprompt routes answer 409 while it is held), runs under one per-app `asyncio.Lock`, and forgets the job's event history (`bus.forget`).
- **UI.** `apiFetch` returns `undefined` on 204. `api.cancelJob`, `api.deleteJob`. `ProjectCard` gets Cancel / delete buttons (`stopPropagation`, `window.confirm`) and a select mode; `routes/index.tsx` a Select toggle, Select all and "Delete selected (n)" (`Promise.allSettled`); `jobs.$jobId.tsx` a header Cancel and a cancelled notice. `JobCancelled` is a known and terminal SSE event (`lib/pipelineStages.ts`; the drift test compares it with the Python enum). `isActiveJob` lives in `lib/jobStatus.ts`.
- **No new setting, dependency or migration.** No ffmpeg call is added (constitution III).
- **Verification.** `pytest` (default run), `pytest -m integration` in CI, `cd web && pnpm test && pnpm build`; every new test mutation-checked. End to end on the owner's stack (T089): `scripts/start.sh`, start a job, cancel it from the home card, check the badge, `pgrep` for ffmpeg/yt-dlp and the `_tmp` folder; select three jobs, delete, check the rows (`psql`), the folders and the export folder.
