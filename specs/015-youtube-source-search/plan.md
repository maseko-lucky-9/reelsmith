# Implementation Plan: YouTube search for clean sources

**Spec**: [spec.md](spec.md)

- **Search route.** `app/routers/sources.py` (`/sources`, registered in `app/main.py`; `/api/sources/...` through `ApiPrefixMiddleware`, ADR-005). `search_youtube` validates `q` (`Query(min_length=1, max_length=200)`, then no control characters, no leading `-`, whitespace collapsed), builds `[sys.executable, -m, yt_dlp, --flat-playlist, --no-warnings, -J, --, ytsearch{limit}:{q}]` and runs it with `yt_dlp_metadata.run_bounded(timeout=settings.youtube_search_timeout_seconds)`, the same killable child runner the metadata preview and the scene indexer use (constitution III). Entries become `YoutubeSearchItem`s; the thumbnail is built from the validated id (`https://i.ytimg.com/vi/<id>/mqdefault.jpg`), not taken from yt-dlp, so no tracking query string reaches the page.
- **Clean route.** `check_youtube_clean` takes `{video_id:path}` so a hostile id reaches the 400, checks `source_check.VIDEO_ID_RE.fullmatch`, and awaits `source_check.check_clean`. `CheckBusyError` becomes 429.
- **Check service.** `app/services/source_check.py`, stateless apart from the cache and the in-flight map:
  - `resolve_stream(id)`: `run_bounded([python, -m, yt_dlp, --no-playlist, --no-warnings, -f <=480p selector, --print duration, --print urls, --, <watch url>])`; `--print` implies no download. Needs an `https://` URL and a finite positive duration.
  - `extract_frames(source, duration)`: four ffmpeg children (the bundled binary through `ffmpeg_tools.resolve_argv`) run with `run_bounded`, concurrently, `-ss` before `-i`, `scale=640:-2`, one JPEG each in a temp dir; a failed position is dropped. A module-level semaphore (2) caps ffmpeg children across all checks. They are asyncio child processes, not `to_thread_cancellable` jobs: the default executor (4 workers, `max_thread_workers`) is shared with transcription and renders, and 4 checks x 4 grabs held it for seconds (review round 1). `LoopLocalSemaphore` (`app/services/loop_local.py`) keeps module-level limits usable on any event loop.
  - `judge_frame` / `judge_frames`: one Ollama `/api/generate` call per frame with `images`, a `format` schema (reason first, so the model writes what it sees before it decides: measured to fix a channel banner read as a caption), `think: false`, `temperature: 0`, `keep_alive: "60s"`; replies that are not the schema are skipped; the loop stops once the vote is settled (spec FR-007).
  - `decide(verdicts)`: two flagged frames reject; confidence = share of frames agreeing x their mean model confidence.
  - `check_clean(id)`: LRU cache (`OrderedDict`, 256) of definite answers, `_inflight` task map (one check per id, `asyncio.shield` so a client that hangs up does not kill a shared check), at most 4 distinct ids at once, a budget of `settings.source_check_timeout_seconds` around the check's own work (stream, frames) and another around its judging, which starts when the check gets its turn with Ollama (`_OLLAMA_SLOT`, one at a time: Ollama is serial, so queueing is not counted against the budget; the queue is at most `MAX_CONCURRENT_CHECKS - 1` long). Verdicts are cached for 24 h. Every failure, including Ollama refusing or timing out, is the `UNAVAILABLE` value, which is not cached.
- **Settings** (constitution I): `source_check_model` ("qwen2.5vl:7b"), `source_check_timeout_seconds` (60), `youtube_search_timeout_seconds` (30), in `app/settings.py` beside the Ollama block. No `.env` edit. `ollama_base_url` is reused; no second model setting (the scene-search spec adds `ollama_vision_model`).
- **UI.** `web/src/routes/sources.youtube.tsx` (`youtubeSourcesRoute`, in `routeTree.ts`). The page owns the query (`useQuery`, 5 minute `staleTime`) and a `settledIds` set. Concurrency: a card's `useQuery` for its check is `enabled` only while its id is among the first 3 results with no answer yet (`admitted`); when a card's check settles it reports up (`onSettled`), which frees the slot for the next one. `staleTime: Infinity`, `retry: false`, no `refetchInterval` or focus refetch, so there is no polling. The "Hide videos with captions" filter reads the captioned set the cards report; a hidden card stays mounted (its query keeps its cache) and renders nothing. "Use this video" calls `navigate({ to: '/workflow', search: { url: item.url } })`, as the home page does; the router percent-encodes it. `web/src/lib/youtubeSources.ts` holds `MAX_CONCURRENT_CHECKS` and `formatDuration`. Sidebar entry "Search YouTube"; home hero gets a third button beside Upload / Google Drive. The app is dark only (`index.css`: "App is always dark"), so the page uses the existing card/zinc tokens; there is no light theme to check.
- **No new dependency, migration or ADR.** The model choice follows ADR-013 (qwen2.5vl:7b is the proven judge); this spec records the prompt and vote.
- **Verification.** `pytest` (default run), `ruff check app tests scripts`, `cd web && pnpm install --frozen-lockfile && pnpm test && pnpm build`; every new default test mutation-checked (51 mutations, see the PR). `pytest -m live tests/e2e/test_live_source_search.py` and `pytest -m integration tests/integration/test_source_check_real.py` are opt-in. End to end on the owner's stack (T125): `scripts/start.sh`, search, wait for the badges, "Use this video" starts a job.
